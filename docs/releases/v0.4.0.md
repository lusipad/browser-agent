# Browser Agent v0.4.0

这次发布把模型配置从“模型条目里混合保存厂商信息”重构为以服务商为中心的管理方式。Endpoint 负责连接，模型记录模型自身信息，Binding 表示某个模型如何通过某个 Endpoint 使用。

## 用户可见变化

- 在服务商页测试 Endpoint，并直接通过 `/models` 同步该服务商实际提供的模型。
- 批量导入、启用、禁用或删除模型接入，同时查看新增、已配置和已下线模型。
- 同一个模型可绑定多个 Endpoint；侧边栏只展示启用的接入。
- 默认接入被禁用时自动回退到首个启用接入。
- Base URL 可填写 `https://api.example.com` 或 `https://api.example.com/v1`。
- “更新模型”改为“检查元数据更新”：远程注册表只补充已有配置的名称、视觉能力、上下文窗口和参考价格，不再替用户决定可用模型。
- 费用按一次请求实际经过的 Binding 统计。

## 设计边界

- Endpoint 的 `/models` 响应是模型可用性的权威来源。
- 远程注册表只是元数据建议源，不新增、删除或改绑本地 Provider、Model、Binding。
- 备用 `/v1` 路径只在 404 时尝试，避免掩盖 401、403、429 或 5xx 等真实错误。
- 旧配置和旧会话在读取时迁移，已有用户无需手工重建设置。

## 已知验证缺口

Chrome 的内部页面策略阻止自动化工具接管 `chrome://extensions` 和 `chrome-extension://` 页面，因此未完成真实扩展设置 UI 的自动化验收。构建、数据迁移、Endpoint 路径处理、模型同步和注册表更新逻辑均由自动化测试覆盖。

## 安装

下载 `browser-agent-0.4.0.zip` 并解压，在 `chrome://extensions` 开启开发者模式，点击“加载已解压的扩展程序”，选择解压后的目录。
